- 分类 taxonomy 版本：`aiden-topic-v1`，固定17个英文 label ID，定义和互斥/遗漏规则以 `backend/app/services/topic_classification/taxonomy.json` 为准。多标签可并存；`other` 与具体类目互斥；模型 `uncertain` 输出空标签；人工状态 `uncertain`、`insufficient_context` 也必须空标签。`other` 不是低置信、上下文不足或未分类。
- 未分类只表示当前 scope 没有与原始来源当前输入 hash 及当前 taxonomy version 同时匹配的模型预测；该计数不加到 `other`。
- 原始来源数、归并审核问题数、归并审核生命周期 `occurrence_count`、预测标签数是不同统计。模型与人工结果分开统计；同一原始来源不会重复进入某个模型版本统计，标签多标签总和不等于来源唯一数。`merged_review_label_counts` 对同一 review 的同一标签去重。`linked_reviews_lifetime_occurrence_count` 是被此 scope 来源链接到的 review 的全生命周期 occurrence 之和，不是该时间范围内的原始问题数。
- 预测按 `(source_id, input_hash, model_version)` 幂等；输入 hash 是 `INPUT_VERSION + 脱敏后分类输入` 的 SHA-256。每次统计重新计算当前来源 hash；输入改变的旧预测/人工标注均不参加 current 统计。更换 taxonomy 的模型结果也不计 current。
- 人工最终标注独立按 `(source_id, input_hash)` 保存，跨模型版本复用且批次绝不覆盖。`confirmed` 必须有标签；`uncertain`/`insufficient_context` 必须无标签。提交时事务内确认用户记录的角色为 `staff`、来源 hash 仍为当前值，并将原值/新值、员工、备注和时间写入 audit。未授权的员工 ID、批次预标或 LLM 结果不能声称是人工确认。
- `FAQ.category` 与 `knowledge_chunks.category` 不会由主题分类器更改。静态映射仅辅助人工预标，不是主题真值，不会自动覆盖目录类目。

### 合成实验训练数据

用户明确选择合成实验时，使用独立实验数据集目录，与默认人审数据集及人工确认准入路径分开。合成预标签不等于人工确认、隐私/语义审核或生产准入；独立歧义挑战题不得混入监督拆分。当前 CLI 提供专用 `prepare-synthetic` 入口；训练、预测、评估消费实验模式数据时必须显式传入 `--synthetic-experiment`，默认人审消费者仍拒绝实验数据。该模式不豁免本地模型基座和 provenance 要求，也不自动下载基座。

从 `backend/` 执行以下命令可把现有三份监督 split 转为独立实验数据集；输出目录必须不存在：


### 人工数据与许可证来源字段

训练/评估不使用自动伪标代替人工真值。每一条 source JSONL 样本至少保留并人工复核以下字段：

| 字段 | 约束 |
| --- | --- |
| `privacy_confirmed`、`privacy_reviewer` | 明确核验脱敏仍保留诉求；每条都要人工确认 |
| `labels`、`classification_status` | 固定 taxonomy 的多标签列表与 `predicted` / `uncertain` / `insufficient_context`；uncertain/insufficient_context 标签必须空，`other`与具体主题互斥 |
| `annotation_status` | `human_confirmed` 才能进入validation/test；`prelabel`仅是未确认建议 |
| `annotation_method`、`annotation_revision`、`annotation_audit` | 记录来源、规则/模型预标版本、审阅修订历史；不可将空审计称作已审核 |
| `prelabel_history` | 保留规则、category映射或LLM建议及逐次复核，不把建议覆写成`human_confirmed` |
| `data_version`、`input_version`、`taxonomy_version` | 冻结数据、topic脱敏/hash语义与类目版本 |
| `source_refs` | 原始来源表/id、会话、用户消息、归并review关联和时间；不以`normalized_question`代替输入 |
| `semantic_cluster`、`annotator` | 语义/会话分组信息与人工标注人，用于防数据泄漏和审计 |

`prepare` 的 `--semantic-review` JSON 必须精确包含 `{ "dataset_hash": "...", "confirmed": true, "reviewer": "...", "revision": "..." }`。先运行 prepare 取得其 `human semantic review required for dataset_hash=...` 报错中计算出的hash，组织人工审核精确数据版本，再签署同一hash；不能先填true绕过核验。测试/验证组必须由人工标签组成，且同会话、同语义簇、精确重复/近重复跨切分会被拒绝。

`--provenance` JSON 必须包含 `model_id`、`revision`、`license`、`source`、`reviewer`、`license_verified`、`chinese_encoder_verified`、`files`；`files` 是基座目录所有文件的相对路径到SHA-256字典，内容需与本地目录一致。曾只读核实公开候选 [hfl/chinese-roberta-wwm-ext模型卡](https://huggingface.co/hfl/chinese-roberta-wwm-ext) 声明 `apache-2.0`，[API revision](https://huggingface.co/api/models/hfl/chinese-roberta-wwm-ext) 为 `5c58d0b8ec1d9014354d691c538661bf00bfdb44`；卡片建议使用Bert相关函数，API类型为 `bert` / `BertForMaskedLM`。这是公开候选许可声明，不是本地权重/tokenizer存在、revision与本地文件checksum匹配或训练数据许可核验。2026-10-07 检查时本地缺该 base/tokenizer 及绑定 provenance；该历史记录不代表后来产物的验证状态。不得自动设置 `license_verified=true` 或下载替代；使用任何本地权重仍须人工复核目录文件 hash 及训练语料许可/隐私。

任务以非阻塞 OS 文件锁限制同一受控目录内跨进程并发；后台线程拥有锁直到成功/失败终态。`queued / running / succeeded / failed / interrupted` 持久保存为文件，列表和详情可刷新。只有拿到锁、确认已无运行持有者时才把遗留运行状态标为中断。批次每完成一个持久化/`stale_source`结果就保存实际 `processed / persisted / stale_source / next_cursor`，失败保留已完成进度和安全stage，不伪造0；`processed` 指已得到持久化结果的来源数，不是尚未完成写入的预测向量数。

Windows 的任务 JSON 读句柄显式共享删除，已存在状态文件通过 `ReplaceFileW` 原子发布；Linux 等平台沿用原子替换。读取中的旧句柄保留完整旧快照，新读者看到完整新状态，避免轮询与进度更新并发时把任务永久留在 queued。该处理不重试任务、不改变有限锁，也不吞掉保存失败。

冻结数据的审核结果按“明确数据模式 + 完整 dataset JSON 内容指纹”单槽复用；不缓存可变数据对象，也不只信任文件内自报的 `dataset_hash`。内容指纹包含全部行、标签来源、隐私/语义审核、分组及切分证据，任何内容或模式变化都重新执行原 `validate_dataset`。任务仍核验接受时文件 SHA 和模型绑定的全部冻结 hashes，历史指标/预测/错误详情仍逐份重建；该复用只避免相同冻结数据反复执行昂贵的近重复分组。
