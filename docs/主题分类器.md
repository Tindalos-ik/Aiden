# 旁路主题分类器

## 状态与边界

**代码已实现，真实训练/评估/生产批量预测尚未验收。** 主题分类是独立旁路，不接入在线 `agent/intent.py`、答复生成、向量索引或 FAQ `category` 写入；当前只对 `low_confidence_questions.original_question` 原始用户问法分类，不用 `review_queue.normalized_question` 替代输入，不混同审核 `issue_types`。源文案经过 topic 专用脱敏后再输出或送模型。

- 分类 taxonomy 版本：`aiden-topic-v1`，固定17个英文 label ID，定义和互斥/遗漏规则以 `backend/app/services/topic_classification/taxonomy.json` 为准。多标签可并存；`other` 与具体类目互斥；模型 `uncertain` 输出空标签；人工状态 `uncertain`、`insufficient_context` 也必须空标签。`other` 不是低置信、上下文不足或未分类。
- 未分类只表示当前 scope 没有与原始来源当前输入 hash 及当前 taxonomy version 同时匹配的模型预测；该计数不加到 `other`。
- 原始来源数、归并审核问题数、归并审核生命周期 `occurrence_count`、预测标签数是不同统计。模型与人工结果分开统计；同一原始来源不会重复进入某个模型版本统计，标签多标签总和不等于来源唯一数。`merged_review_label_counts` 对同一 review 的同一标签去重。`linked_reviews_lifetime_occurrence_count` 是被此 scope 来源链接到的 review 的全生命周期 occurrence 之和，不是该时间范围内的原始问题数。
- 预测按 `(source_id, input_hash, model_version)` 幂等；输入 hash 是 `INPUT_VERSION + 脱敏后分类输入` 的 SHA-256。每次统计重新计算当前来源 hash；输入改变的旧预测/人工标注均不参加 current 统计。更换 taxonomy 的模型结果也不计 current。
- 人工最终标注独立按 `(source_id, input_hash)` 保存，跨模型版本复用且批次绝不覆盖。`confirmed` 必须有标签；`uncertain`/`insufficient_context` 必须无标签。提交时事务内确认用户记录的角色为 `staff`、来源 hash 仍为当前值，并将原值/新值、员工、备注和时间写入 audit。未授权的员工 ID、批次预标或 LLM 结果不能声称是人工确认。
- `FAQ.category` 与 `knowledge_chunks.category` 不会由主题分类器更改。静态映射仅辅助人工预标，不是主题真值，不会自动覆盖目录类目。

```powershell
# 首先查看当前 CLI
.\.venv\Scripts\python.exe -m scripts.topic_classifier --help

# 从 low_confidence_questions 导出限量脱敏源。--after 使用 ISO8601时间戳,来源UUID 的单参数游标。

# 只有训练成功生成 metadata.json 才能执行预测/批处理/编码器评估。
.\.venv\Scripts\python.exe -m scripts.topic_classifier predict --artifact-dir .tmp/topic-model --input .tmp/topic-test.jsonl --output .tmp/topic-predictions.json
.\.venv\Scripts\python.exe -m scripts.topic_classifier batch --artifact-dir .tmp/topic-model --device cpu --limit 100 --batch-size 16 --after 2026-10-01T00:00:00Z,来源UUID
.\.venv\Scripts\python.exe -m scripts.topic_classifier stats --model-version 训练artifact中的model_version
.\.venv\Scripts\python.exe -m scripts.topic_classifier evaluate --dataset .tmp/dataset.json --artifact-dir .tmp/topic-model --output .tmp/topic-eval.json

# 规则、真实本地编码器和明确授权后的付费LLM三方案比较；LLM不得隐式使用线上密钥。

.\.venv\Scripts\python.exe -m scripts.topic_classifier evaluate --dataset .tmp/dataset.json --artifact-dir .tmp/topic-model --llm-model <显式模型名> --llm-base-url <显式兼容端点> --allow-paid --output .tmp/topic-eval-comparison.json
Remove-Item Env:TOPIC_LLM_API_KEY

# 人工最终状态须由真实 staff 显式提交，输入hash须来自当前 source export。
.\.venv\Scripts\python.exe -m scripts.topic_classifier review --source-id 来源UUID --input-hash 当前脱敏输入SHA256 --staff-id 真实员工UUID --labels logistics order_change --status confirmed --note 已核验
```

训练 API/CLI 默认参数一致：`epochs=3`、`batch_size=16`、`learning_rate=2e-5`、`max_length=256`、`seed=42`、`device='cpu'`；CLI 已显式暴露 `--learning-rate`、`--max-length`、`--seed`，且训练 metadata 会写出完整 `train_args`、checkpoint selection（validation BCE loss 最小值/epoch）、随机种子、dataset/split hashes、基座 provenance、文件校验、验证阈值与版本。`stats` 标签计数分模型预测/人工最终/归并review唯一标签；不把 prediction 变成人工标签，也不对 no-current 计入 `other`。

### 人工数据与许可证来源字段

训练/评估不使用自动伪标代替人工真值。每一条 source JSONL 样本至少保留并人工复核以下字段：

| 字段 | 约束 |
| --- | --- |
| `privacy_confirmed`、`privacy_reviewer` | 明确核验脱敏仍保留诉求；每条都要人工确认 |
| `labels`、`classification_status` | 固定 taxonomy 的多标签列表与 `predicted` / `uncertain` / `insufficient_context`；uncertain/insufficient_context 标签必须空，`other`与具体主题互斥 |
| `annotation_status` | `human_confirmed` 才能进入validation/test；`prelabel`仅是未确认建议 |
| `annotation_method`、`annotation_revision`、`annotation_audit` | 记录来源、规则/模型预标版本、审阅修订历史；不可将空审计称作已审核 |
| `prelabel_history` | 保留规则、category映射或LLM建议及逐次复核，不把建议覆写成`human_confirmed` |
| `data_version`、`input_version`、`taxonomy_version` | 冻结数据、topic脱敏/hash语义与类目版本 |
| `source_refs` | 原始来源表/id、会话、用户消息、归并review关联和时间；不以`normalized_question`代替输入 |
| `semantic_cluster`、`annotator` | 语义/会话分组信息与人工标注人，用于防数据泄漏和审计 |

`prepare` 的 `--semantic-review` JSON 必须精确包含 `{ "dataset_hash": "...", "confirmed": true, "reviewer": "...", "revision": "..." }`。先运行 prepare 取得其 `human semantic review required for dataset_hash=...` 报错中计算出的hash，组织人工审核精确数据版本，再签署同一hash；不能先填true绕过核验。测试/验证组必须由人工标签组成，且同会话、同语义簇、精确重复/近重复跨切分会被拒绝。

`--provenance` JSON 必须包含 `model_id`、`revision`、`license`、`source`、`reviewer`、`license_verified`、`chinese_encoder_verified`、`files`；`files` 是基座目录所有文件的相对路径到SHA-256字典，内容需与本地目录一致。已只读核实公开候选 [hfl/chinese-roberta-wwm-ext模型卡](https://huggingface.co/hfl/chinese-roberta-wwm-ext) 声明 `apache-2.0`，[API revision](https://huggingface.co/api/models/hfl/chinese-roberta-wwm-ext) 为 `5c58d0b8ec1d9014354d691c538661bf00bfdb44`；卡片建议使用Bert相关函数，API类型为 `bert` / `BertForMaskedLM`。这是公开候选许可声明，不是本地权重/tokenizer存在、revision与本地文件checksum匹配或训练数据许可核验。当前本地无该base/tokenizer及来源/checksum绑定provenance；不得自动设置 `license_verified=true` 或下载替代。拿到本地权重后仍须人工复核目录文件hash及训练语料许可/隐私。

### 三方案评估与真实运行状态

`evaluate` 的完整对照要求规则、冻结的本地编码器artifact、以及用户明确授权后配置模型/端点/key并传入 `--allow-paid` 的 LLM；每方案报告独立冻结test上的逐类与macro/micro F1、覆盖、状态混淆/人工纠错需求、耗时。在线本地仍无test artifact；尚无任何真实三方案分类指标，不能把空表、缺模型、缺人工测试类目解释为分数0。当前无付费请求，LLM usage/cost 未被实测/无法知晓，不等于cost=0。冻结编码器评估校验artifact中的 `dataset_hash` 和完整 `split_hashes`；重seed重新切分的test集会hard fail，而不是误报为独立测试。

当前不推荐生产启用，也不建议仅凭这6条数据投入微调；目前只适合限量只读导出与人工标注。真实三方案状态如下，缺失值用“未评估”而非0：

| 方案 | 真实指标/吞吐/成本 | 未评估原因 |
| --- | --- | --- |
| rules | 未评估 | 无经人工核验的冻结评估集 |
| LLM | 未评估 | 无人工测试集且没有付费调用授权；usage/cost未知 |

没有真实模型 bad case 或人工纠错记录；不能把fixture测试样例当作代表性错误或纠错证据。当前仅有6条未经隐私确认的来源样本。
