# 可观测性

## Langfuse

在线客服的每条新消息在 `stream_message()` 中构建并运行一次 `aiden_support` LangGraph。配置 Langfuse 后，`build_support_graph()` 在图编译完成时绑定一次 `CallbackHandler`，回调随图传递给节点、模型调用和 `ToolNode`，形成同一条 trace。客户端对已完成消息的幂等重放不重新运行图，也不会产生新 trace。

### 配置

在 `backend/` 下执行 `python -m pip install -r requirements.txt`，再在未提交的 `backend/.env` 中填写以下三项，并重启 API：

```dotenv
LANGFUSE_PUBLIC_KEY=<项目公钥>
LANGFUSE_SECRET_KEY=<项目私钥>
LANGFUSE_BASE_URL=<Langfuse 云区域或自部署地址，例如 https://cloud.langfuse.com>
```

三个值都非空才启用上报；留空时在线对话照常运行。环境变量示例见 `backend/.env.example`。实际密钥不要写入示例文件或版本库。Langfuse 接收完整的对话 Prompt、用户消息、订单工具结果及知识检索内容，应为该项目设置合适的访问权限和数据保留策略。

`langfuse.langchain.CallbackHandler` 还要求安装 `langchain`。它已列入 `backend/requirements.txt`，`start.ps1` 也会检查该导入；已有虚拟环境若缺少该包，需要重新安装依赖。缺包时会在构建 Agent 图时抛出 `ModuleNotFoundError`，这属于本地依赖错误，不是 Langfuse 云端连接错误。

### 查看一条请求

发送一条新的在线客服消息后，在 Langfuse 的 Traces 页面打开名为 `aiden_support` 的记录，展开节点调用树。根节点对应一次 LangGraph 运行；`recognize_intent`、`route_intent`、`generate` 等节点显示输入、输出和耗时。模型子节点显示实际发送的 Prompt、模型回复、耗时及 token 用量。`query_order`、`query_logistics` 或 `search_faq` 工具子节点显示调用参数和返回值；`search_faq` 的返回值包含召回的知识条目、引用编号及可用的重排分数。

图内的模型使用流式输出，启用 Langfuse 时会向 OpenAI 兼容服务请求流式 usage。准确 token 数取决于模型服务是否返回 usage；未返回时 Langfuse 可能无法显示准确值。非模型节点和工具本身没有模型 token 消耗。当前检索的向量化、Milvus 召回和重排由 `search_faq` 工具内部执行，这些内部步骤没有各自的 LangChain 回调节点；可在工具返回值中查看最终检索结果，并在工具节点上查看其合计耗时。

回调只覆盖实际运行到的图分支。模型配置缺失、会话检查失败或幂等重放发生在图运行之前，因此不会出现这次运行的 Langfuse trace。Langfuse SDK 异步上报，界面中的新 trace 可能稍晚出现。

### 连接与上报排查

- 先核对 `LANGFUSE_BASE_URL` 是否指向项目所在云区域或自部署实例，并检查运行 API 的进程是否继承了 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY`。失效的本机代理会让请求在到达 Langfuse 前就被拒绝；修正代理或按实际网络设置直连后再检查。诊断命令的环境与 API 进程可能不同，不能只凭其中一方的代理设置推断另一方。
- Langfuse 3 的回调经 `/api/public/otel/v1/traces` 异步上报。日志中的 `Failed to export spans batch ... Read timed out. (read timeout=0)` 表示某批次超过导出期限；当前 SDK 默认超时为 5 秒，日志中的 `0` 不代表项目把超时配置成了 0。部分批次失败不等于所有 trace 都未送达，应到 Langfuse 界面核对对应时间的观测记录。
- 新建的 Langfuse Cloud 组织可能对旧版 `GET /api/public/traces` 返回 `410 LEGACY_API_UNAVAILABLE_FOR_NEW_ORGANIZATION`。这是旧查询接口不可用，不是密钥错误，也不能据此判断 OTLP 上报失败。查看实时数据可用 Langfuse 界面或新版 `GET /api/public/v2/observations`；若代码需要读取追踪数据，应按云端提示迁移读取接口。
