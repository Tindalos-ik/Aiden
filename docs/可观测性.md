# 可观测性

## 在线上报与员工只读控制台

在线客服每条真正的新消息在 `stream_message()` 中构建并运行一次 `aiden_support` LangGraph。图编译出口绑定唯一 `SupportCallbackHandler`（继承 Langfuse 3 的 `CallbackHandler`），随图传播到节点、模型和工具，不重复添加节点回调。相同消息的幂等重放在构建图前直接返回，员工查询也不运行图、不调用模型、不产生新的客服 trace。

员工页面不是外链或 mock：通过项目后端只读查询已确认支持的 Langfuse `GET /api/public/v2/observations`，重建真实观测树，并在本地对唯一 observation 汇总。无真实数据或连接失败不会生成示例数据。员工 Cookie 和 `current_staff` 保护每个端点；未登录 401、普通用户 403。上游异常仅影响查询，不影响在线业务。

### 配置与隐私

在未提交的 `backend/.env` 中配置三项并重启 API：

```dotenv
LANGFUSE_PUBLIC_KEY=<项目公钥>
LANGFUSE_SECRET_KEY=<项目私钥>
LANGFUSE_BASE_URL=<项目所在区域或自部署地址>
```

三项都非空才启用；密钥不进入浏览器或响应。项目沿用已安装的 Langfuse SDK，不增加查询依赖。`langchain` 已列入 `backend/requirements.txt`；缺依赖属于本地安装错误，而不是上游认证问题。

**上报与员工展示的隐私边界不同。** 原有 LangChain 回调向 Langfuse 上报完整 Prompt、用户消息、模型输出及工具结果，可能包含订单或其他敏感信息；需设置项目权限与保留策略。员工控制台不请求 `io` 字段，不返回 inputs、outputs、Prompt、订单结果、电话号码、用户正文、任意 metadata 或原始异常内容。只展示真实结构 ID、父 ID、受控节点名称、模型、状态、时间、Token 用量及受控内部关联，不展示费用。非白名单名称显示“observation”（未展示名称），不是伪造节点；外部 URL 当前始终为空，避免泄露项目地址或提供不受控链接。

新运行的根回调只补充以下受控关联/状态，并复用已有归因上下文：

- `conversation_id`、`assistant_message_id`：来自服务端已创建的内部行 ID；不增加用户 ID、订单号、电话或文本。
- `aiden_source=online/evaluation`：图构建时确定。评估仍用同一个图，但明确与线上隔离。
- `aiden_completion=success`：仅根 `on_chain_end` 成功结束事件写入。这是**图执行完成**，不是客户业务成功、回答质量或供应商请求成功率。
- `recognized_intents`：复用原有 `{intent, goal}` 封闭上下文语义，不是新增业务归因。`goal` 仅保留 `SupportRequest` 原合法目标枚举；根 observation 同样安全。不复制实体或用户原文。仅当实际根输出包含 requests 数组时记录；实际 requests=[] 可记录空上下文，缺失 requests 不假装已识别。

根关联在首次根 `on_chain_start` 同时写入根 observation 和 trace；完成与意图也同时写入二者，以兼容不同 v2 记录表示。SDK metadata 按 key 展平设置 OTEL 属性，后续更新不覆盖其他已存在 key。写入失败不阻断业务。旧 trace 级 `recognized_intents` 更新不保证 v2 observation metadata 可读；控制台不把 generation 归因桶冒充已识别根意图，缺记录显示未记录。历史无明确 `aiden_source` 的记录划入 `other / unrecorded`，不能默认线上，因为原有评估也叫 `aiden_support`。员工选择“其他/来源未记录”可查看这些真实历史；默认线上仅含明确标记 online 的记录。

### API 与可用性

全部为 GET：

| 路径 | 行为 |
| --- | --- |
| `/api/observability/status` | 只检查配置，返回 `configured_unverified` 或 `unconfigured`，不主动验证上游 |
| `/api/observability/overview` | 请求根数量、generation 数量、延迟、Token 趋势、归因与确定性分析；内部费用计量字段仍保留，员工页面不展示 |
| `/api/observability/traces` | 筛选后的真实 trace 列表，页面分页 |
| `/api/observability/traces/{trace_id}` | 指定 trace 在同一时间范围内的真实 observation 平面父子树与时间线 |

overview/list/detail 的 `start_at/end_at` 必须带时区，默认最近 24 小时，范围必须为正且最多 31 天，转换为 UTC。详情必须传入列表相同范围；范围外子节点可能缺失，不假装完整历史。`max_observations` 默认 5000、最大 10000；上游 cursor 逐页读取、按 observation ID 去重，直到无 cursor 或达到限额。截断明确标记，所有指标仅代表所读批次。重复 cursor 也标记不完整，不无限循环。列表 `page` 默认 1、`page_size` 默认 20、最大 100。

员工页面使用相对时间范围（最近 24 小时、7 天或 31 天）时，点击刷新会将结束时间推进到点击时的当前时间，并按原时长重新查询 overview、列表和已选详情，避免始终查询页面初次打开时的窗口。自定义时间范围则保留**已应用**的起止时间，刷新在同一范围重新读取这些数据；未应用的输入草稿不会偷偷改变查询范围。刷新不是触发客服请求，也不调用模型。

`source` 仅允许 `aiden_support` 或 `other`，没有线上/离线混算的 all 汇总。可选 `model`、封闭 `intent`、`status=success/error/unknown`、`conversation_id`、`message_id`。模型/意图筛选先选择请求，再保留该请求全部 generation，包括共享分类；意图可匹配真实根记录或 generation 归因，但列表的“已识别意图”仅来自根记录。详情仅按 ID 和时间界限读取，不按列表的模型/意图丢弃节点。

统一 envelope 含 `state/message/queried_at/latest_record_at/coverage/availability/data`：

- `ready`：查询已验证且有匹配记录；`empty`：查询已验证但范围没有匹配记录。
- `auth_failed`：上游 401/403；`connection_failed`：连接、超时或读取失败。
- `unsupported`：目标不支持该读取接口，包括 404/405/410/501；不解释成错误密钥，不伪造回退数据。
- `configured_unverified/unconfigured`：配置与查询验证分开表达。

coverage 显示上游读取数 `observations_read/generations_read`、匹配范围 `matched_generations/matched_traces`、时间范围、限额与 truncated。`latest_record_at` 仅当前 source 和筛选匹配记录中的最近时间；无匹配为 null，不显示别的来源最新记录。availability 显示 configured、query_verified、upstream 和异步不完整声明。查询时间不是上报完成时间；SDK 异步上报可能迟到。不同服务器版本能力不同；目前只使用实际验证支持的 v2 observation 端点，不猜测任意 metadata 聚合或其他旧接口可用。

### 真实树、状态与延迟

每个 observation 使用上游真实 ID 与 `parentObservationId`。不会把图固定节点串成假时间线；并行分支保持真实父子关系，节点耗时不能相加为根耗时。缺父节点、跨读取边界可能性及截断分别显示；缺父身份无法确认，不生成虚构父节点。`search_faq` 只展示工具整体延迟，其向量化、召回、重排没有新增内部 instrumentation。

请求量是**真实图根 observation 数**，不是 session 数。实际目标 v2 同时返回无结束时间的 `t-<trace_id>` 包装根和带真实结束时间的同名 LangChain 图根；优先 `is_langchain_root` 的真实图根，不把包装根重复计数，但详情保留全部真实返回行和父 ID。根 ERROR 为 error；显式完成标志且有结束时间为 success；其余 unknown。普通子 generation 出错不会把根变为 error，缺失状态绝不默认为 success。旧 SDK 控制流异常可结束却不标 ERROR，所以历史仅 DEFAULT+结束时间也归 unknown。

延迟从真实 start/end 差值计算毫秒；缺任一端或负值不进入样本。平均、P50、P95 从原始样本计算，分位数使用排序样本线性插值，不计算“平均的平均”。每日 UTC 趋势展示根请求量、generation 数、延迟统计和 Token。

员工“观测与用量”页面使用 `overview.data.token_trend`：按唯一 generation **实际开始 UTC 日 + 真实模型 + 归因桶** 分组，返回 `date/model/bucket/generations/tokens`，不包含费用。共享 `intent_classification` 与缺归因 `unattributed` 均有独立趋势/明细行。各维度分组的已确认 Token 加总等于总用量，不使用根记录聚合值。前端用量区域的模型/桶下钻只筛这些 generation 维度；服务器主模型/意图筛选仍先选整请求并保留共享调用。主 `trend` 是请求根开始日口径，不作为业务意图/模型用量趋势。缺真实开始时间保留 `date=unknown`，不发明日期；UTC 日桶与浏览器本地显示时间明确分开。原 `cost_trend` 员工契约已替换，不提供兼容别名。

### Token 用量、内部费用计量与意图归因

仅唯一 `GENERATION` 行纳入聊天模型 tokens/费用，不累加 trace 费用与子 generation，不把多意图 trace 金额复制到每个意图。

- `cost_intent_<封闭意图>` 或 metadata `cost_intent` 标记真实业务模型调用。
- `cost_bucket_intent_classification` 或 metadata `cost_bucket=intent_classification` 是共享分类桶，只单列一次。
- 根 `recognized_intents` 是上下文，不能直接成为成本分组或分摊权重。
- 没有真实归因信息的 generation 是 `unattributed`。

输入/输出/total 仅汇总同一回调 `on_llm_end` 从真实 `LLMResult` 的 `message.usage_metadata` 或 `llm_output.token_usage` 读取的计数，记录为受控 `aiden_usage_source=provider` 和 `aiden_provider_usage`。每字段提供 known/missing 覆盖；缺字段不推算 total，null 与确认 0 不同。**历史没有来源标志的值不计入已确认 provider 汇总，tokens 为 unknown**；详情可单独展示“Langfuse 记录值，来源未核验”的 `usage_details`。cached/reasoning 只展示安全白名单细项，不再次叠加到 total。本站不根据字符数估 tokens，也不把 Langfuse tokenizer 推算值当作 provider usage。当前在线模型请求流式 usage，仍依赖服务端响应；缺失响应 usage 标为 unknown。回调仍仅在图出口绑定一次，没有额外逐节点绑定。

**员工页面仅展示 Token，不展示费用汇总、币种、金额、费用排名或缺金额提示。** 本次展示调整不删除 Langfuse 费用追踪，不改 SDK 字段组、`cost_bucket/cost_intent` 埋点或内部计量。服务响应仍保留 `costs/cost_details`、主 `trend.known_costs` 和 `data_quality.cost_recorded/cost_missing` 等内部字段，前端不消费这些字段；仅旧费用页面使用的 `insights.cost_contributions` 及其专用计算已移除。

内部费用优先取 `costDetails.total`，若该字段缺失，采用同一条 v2 observation 的 `totalCost`。已安装 SDK 3.15.0 的 `observations_v_2/client.py` 明确 `usage` 字段组同时包含 `usageDetails/costDetails/totalCost`，且 `totalCost` 是 USD 总额；不存在需要额外请求的独立 `cost` 字段组。`Observation.costDetails` 合同明确 total 是所有非 total 费用指标之和或直接上报总额。读取方不自行补算分项、不叠加两个总额、不回退到旧 `calculatedTotalCost`、不按模型名猜价格。已知小计与 known/total generation 覆盖保留在内部结构中，确认 0 与 null 不同；只汇总唯一 generation，不叠加根/父 span 与 trace 聚合费用。

v2 `totalCost` 的官方币种固定为 USD；采用该字段时，不因同记录其他 `currency/costCurrency` 字段而改贴币种，也不做换汇。原有 `costDetails.total` 的显式币种分列行为保持不变。内部概览、详情、贡献、主趋势及质量覆盖复用同一逐调用总额读取口径，确认 0 优先于其他总额，不重复计算根容器费用。

官方定义：上报费用优先，否则由匹配模型价格计算。v2 解析后的 costDetails 不提供逐行 provided/calculated 来源标记；内部金额来自 Langfuse 计价，不是供应商账单，也不承诺已校验项目所有自定义模型价格。未计入工具、DB、GPU、embedding、rerank 的消耗，不能声称这些免费。

参考：[Langfuse token/cost tracking](https://langfuse.com/docs/observability/features/token-and-cost-tracking)、[公开 API 与 v2 字段/分页](https://langfuse.com/docs/api-and-data-platform/features/public-api)。自定义模型需在目标项目配置正确价格，历史缺失不会靠名称或 metadata 自动恢复。

### 分析与验证边界

概览返回 `insights`（仅员工语言的用量事实 `facts` 和统计限制 `limitations`）、`slow_items`（同一筛选批次的前五条慢请求和慢步骤，附真实 trace/observation ID 供跳转）及 `data_quality`，不再返回带技术 ID 的旧 `analysis` 字符串。事实区不嵌入 ID，也不包含费用或缺金额话术；追溯信息只进入结构字段。所有统计和贡献均基于筛选后的整条请求与唯一观测，不限于列表当前页；截断时明确不是全量排名。共享识别用量不分摊，不根据耗时推断异常阈值、模型质量或优化因果。

`data_quality.provider_verified` 与 `tokens.known_generations` 同口径：marker 为 provider、原始计数字典存在且 input/output/total 三字段都是有效非负有限数。缺一字段只计已知字段，不补算 total，并提示部分用量。员工页面仅按实际记录区分用量未记录、历史来源未核验及部分用量；内部金额覆盖字段不展示。envelope coverage 同时给出读取数、匹配观测数、来源匹配请求数、来源排除数及其他筛选排除数；排除计数仅属于已读批次。完整读取时 empty_reason 区分整个时间范围无记录、来源排除、其他筛选排除；截断时 empty_reason 为 null，不推断全范围无匹配。facts 的“可确认处理次数”与 counts.roots 采用相同真实图根口径，另列与列表 total 一致的匹配请求记录组数；没有图根不猜测处理次数或根耗时。配置非空仍只是 configured_unverified，真实查询 ready/empty 才表示本次读取成功。
