# 测试问题与参考答案

本页对应 [`sql/test.sql`](../sql/test.sql)。先完成 Alembic 迁移，再通过 VS Code 的 MySQL 插件连接本机 `127.0.0.1:3307`、数据库 `aiden`，执行整个 SQL 文件。脚本向 15 张应用表写入固定 ID 的演示数据；`alembic_version` 是迁移管理表，不应手工插入测试行。重复执行脚本不会修改已有的同 ID 测试行。

前端可使用 `sql.customer@aiden.test` / `aiden123` 登录。以下时间均为数据库保存的 **UTC 时间**。所有订单、政策和回复都是虚构测试数据。

**当前工具行为：** remote 模式下，客服 Agent 可查询本人订单、物流、售后申请和工单，也可查询现行政策、检索知识库及登记工单。知识检索先经 Milvus 向量召回、再回 MySQL `knowledge_chunks` 取权威原文，只返回已向量化的块。若先导入 `sql/test.sql`，测试账号可查询属于自己的测试业务记录；知识类问题还需要把 `backend/knowledge/` 的文档与启用中的 faq 行建成知识库（`import-markdown`、`import-faq`、`vectorize`）。没有匹配记录时工具返回空结果，模型应据实说明。

售后申请、政策版本和工单分别由专用工具读取，不能把 `search_faq` 的知识块当成这些业务记录。`create_ticket` 只登记待处理工单，不创建退款申请或实时接入人工。关于参数、权限和 SSE 的说明见 [`tools.md`](tools.md)，检索链路与验收方法见 [`RAG.md`](RAG.md#在线语义检索)。

## 接入在线向量检索后新增可回答的问题

`search_faq` 已从 `faq` 表关键词匹配改为 Milvus 向量召回（检索链路见 [`RAG.md`](RAG.md#在线语义检索)）。它检索的是 `knowledge_chunks`，因此可回答范围取决于**知识库建了什么**，而不是 `faq` 或 `policies` 表里有什么。

### 前置条件

下列问题要能被回答，知识库必须先建好：

```powershell
Set-Location D:\myproject\Aiden\backend
.\.venv\Scripts\python.exe -m scripts.build_knowledge_base import-markdown
.\.venv\Scripts\python.exe -m scripts.build_knowledge_base import-faq
.\.venv\Scripts\python.exe -m scripts.build_knowledge_base vectorize
```

同时 Milvus 与 BGE 向量服务必须在运行；任一不可用时 `search_faq` 返回通用错误结果，而不是退回关键词检索。知识库构成（`backend/knowledge/` 的 4 份文档 + `faq` 表 2 行）见 [`RAG.md`](RAG.md#已验证的范围-1)。

### 仍有限制的问题

| 问题类型 | 示例 | 原因 |
| --- | --- | --- |
| 未生效或已停用的政策 | 测试退货政策是什么？ | `query_policy` 只返回当前启用且生效的版本；否则说明无法核实现行条款 |
| 未明确的业务目标 | 我的包裹到哪了？ | 物流需要先确认本人订单目标，必要时列出近期订单供选择 |
| 尚未接入的业务写操作 | 帮我直接提交退款申请、接入真人客服 | 目前只能登记待处理工单，不能直接创建退款申请或实时接通人工 |
| 知识库外的常识或企业内部信息 | 你们公司的营收是多少？ | 知识库没有该内容，提示词禁止用模型记忆或常识补答 |

注意一个容易误判的边界：**「运费险」在知识库和 `policies` 表里可能有不同粒度的内容。** 回答当前政策条款应以 `query_policy` 返回的有效版本为准；知识库中「退货政策 > 运费承担规则」只支持其实际召回的内容，不能据此补造保单细节。

### 验证方法

先确认知识库本身建好了、且向量维度与集合一致：

```powershell
Set-Location D:\myproject\Aiden\backend
$env:PYTHONIOENCODING="utf-8"
.\.venv\Scripts\python.exe -m scripts.build_knowledge_base stats
```

输出应显示 `vectorized` 条数（当前 38）以及 `embedding_model` / `embedding_dimension`；后两者必须与 Milvus 集合建表时的维度一致，不一致时检索会直接报错而不是返回错结果。要看具体入库了哪些块（含问法与 `embedding_text`）：

```powershell
.\.venv\Scripts\python.exe -m scripts.build_knowledge_base chunks --limit 5
```

召回质量可以脱离 LLM 单独核对，用它确认某个问法到底命中了哪几块、相似度多少：

```powershell
.\.venv\Scripts\python.exe -c "from app.services.rag.retrieval import semantic_search; [print(f'{h.score:.4f}  {h.chunk.category} > {h.chunk.section_path}') for h in semantic_search('退货的运费谁承担', limit=3)]"
```

本文各表中的问法在 512 维 `bge-small-zh-v1.5` 与当前 38 个知识块下实测 top-1 命中，相似度大致落在 0.68 至 0.89 之间。

更完整的向量查看脚本（总览、按块查看原文与向量、检索详情）是 `backend/.tmp/view_vectors.py`，工作区里都有这个临时目录。它不进版本库，因此换机器或清理临时目录后需要重建；日常核对用上面的命令就够。

要一并核对最终回答，就用浏览器登录演示账号提问；真实链路会依次经过意图识别、`search_faq` 的向量检索与最终回答生成。注意在线 Agent 需要 `OPENAI_THINKING_MODE=disabled`，否则带工具的多轮回复会被服务端拒绝，原因见 [`RAG.md`](RAG.md#思考模式必须关闭)。
