# Aiden 数据库实现总结

## 本次完成内容

- 使用 Docker Compose 部署 MySQL 8.4，配置 utf8mb4、命名数据卷、健康检查和可配置的本机端口；Compose 只启动数据库。
- 新增环境变量示例 deploy/.env.mysql.example，包含数据库账号、占位密码、端口和本机连接用的 DATABASE_URL；没有创建或写入真实密码文件。
- 使用 SQLAlchemy 2.x 为设计文档中的 14 张表建立 ORM：用户、商品、SKU、订单、订单商品、包裹、物流轨迹、售后申请、政策、FAQ、会话、消息、工单和未解决问题。
- 为模型定义主键、外键、唯一约束、状态检查和常用查询索引。金额使用 DECIMAL/Decimal；订单商品保留名称、规格、SKU 和成交价快照；政策按键和版本唯一，并记录生效区间。
- 增加 Alembic 初始迁移以及读取 DATABASE_URL 的延迟 Engine/Session 代码。导入模型不会自动建表。
- 提供少量数据访问查询：按用户读取订单、按用户和订单读取物流轨迹、查询指定时点的生效政策、按用户读取会话消息。订单、物流和会话消息查询都在 SQL 中限制 user_id。
- 新增 docs/database-schema.md，说明表关系、字段假设、PowerShell 环境配置、启动 MySQL、执行迁移和关闭容器的方法。
- 数据库依赖独立列在 backend/requirements-db.txt。

## 数据层接入入口

从 backend 目录运行服务并导入：

- app.persistence.mysql.get_session：可用作 FastAPI 依赖的 Session 生成器。
- app.persistence.mysql.session_scope：自动提交或回滚的事务上下文管理器。
- app.persistence.mysql.get_engine 和 app.persistence.mysql.get_session_factory：根据进程环境中的 DATABASE_URL 延迟创建并缓存引擎与 Session 工厂。
- app.persistence.mysql.models：14 张表的 ORM 类和 Base。
- app.persistence.mysql.queries：list_user_orders、list_order_tracking_events、get_effective_policy、list_conversation_messages。

## 本机操作

从项目根目录复制并编辑环境示例，设置本机密码，并保持 DATABASE_URL 与账号、数据库名和端口一致：

    Copy-Item deploy/.env.mysql.example deploy/.env.mysql
    docker compose --env-file deploy/.env.mysql -f deploy/compose.mysql.yml up -d mysql
    Set-Location backend
    python -m pip install -r requirements-db.txt
    $urlLine = Get-Content ..\deploy\.env.mysql | Where-Object { $_ -match '^DATABASE_URL=' } | Select-Object -First 1
    $env:DATABASE_URL = $urlLine.Substring('DATABASE_URL='.Length)
    .\.venv\Scripts\alembic.exe -c alembic.ini upgrade head

迁移完成后从 backend 返回项目根目录并关闭容器：

    Set-Location ..
    docker compose --env-file deploy/.env.mysql -f deploy/compose.mysql.yml down

down 会保留命名数据卷。真实密码只放本机环境文件，不要提交。
